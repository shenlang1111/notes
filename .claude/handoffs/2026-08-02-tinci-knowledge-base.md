## 2. 重要上下文（接替者必须知道）

### 2.1 用户是谁（画像）

- **身份**：天赐材料（Tinci Materials）日化销售，非技术背景，但对表活有基础概念（认识羟基/羧基）
- **沟通风格**：直接不拐弯（"你又忘了部署"）、分情况沟通（知道找谁）、追问型、在乎真实感（宁要"不确定"不要假装懂）
- **性格特质**：务实、有主见（建议需给理由）、长线思维（积累型）、会用人（懂分工）
- **最在意**：说到做到（信任比能力更难恢复）、真实反馈、从工具到伙伴、内容不丢
- **学习方式**：通过和 AI 对话讨论概念，自动整理到知识库；多窗口并行（主 agent + 闲聊/智能体/日志/UI 美化）
- **偏好**：通俗类比（漏斗/乐高零件/水外套）、表格、销售实战视角；反感文字墙、反感被选项框住、反感"急着执行不先理解"

### 2.2 核心诉求

- 手机随时可看（不依赖 WiFi，流量即可访问）
- AI 随时可调用（内容同时存 HTML + Markdown）
- 持续增量迭代
- **"懂你"仅限闲聊 AI**（2026-08-02 用户拍板）：其他 AI（含主 agent）只用保持专业性，不需要懂用户个人

### 2.3 关键机制（务必遵守）

- **版本号报告制**：新 AI 开工读 5 份文档并**报告版本号**（防止"说读了其实没读"）
- **铁律 0**：回复"完成"前必须展示 DoD 自检清单（CHANGELOG/双格式/部署/--expect），**没有 = 未完成**，用户可直接判定
- **响应四问**：理解了吗 / 讨论还是执行 / 读了吗 / 谁拍板——模糊的讨论型任务先复述确认
- **并行分派默认**：≥3 步任务拆子代理（各碰各的文件，**同一文件串行**）；关键产出配审核 agent
- **唤醒识别**：用户提"别处/其他 AI/最近修改"→ 先按 LastWriteTime 扫共享文件夹，不说"看不到"
- **翻库规则**：知识类问题必先查库再答——"先翻库、再开口；带出处、不编造；翻不到、说没有"（完整纪律见 `.trae/skills/fanku/SKILL.md`）
- **AI 工作记录留痕**：干完活到 `domains/思考收件箱/ai-worklog.html` 登记一行（日期 + 名字 + 做了什么 + 涉及位置），其他 AI 靠它知道谁干过什么
- **机制更新广播**：新增协作机制（页面/规则/skill/流程）后到 `domains/思考收件箱/mechanism-updates.html` 追加一条（日期+机制+去哪读+谁加的），新 AI 到岗先读它
- **团队任务板**：多人协作任务在 `team-task-board.html` 登记/认领；知识库定期做 `kb-health-checklist.html` 健康度盘点

### 2.4 智能体方向（用户原话的深度理解）

要的不是"更聪明的机器人"，而是"**住在知识库里的、都认识他的专家团队**"——共享知识库当大脑、共享"懂你"档案当记忆，各 AI 专业、直接对话、共同成长。用户不当协调者，机制要让 AI 自己运转。

## 7. 已知的坑（Gotchas）

- 验证线上用 **Node fetch**（PowerShell 的 Invoke-WebRequest 抓 GitHub Pages 会误报 404）
- **同一文件编辑必须串行**（并行编辑会互相覆盖——多次踩坑）
- **多 AI 并发部署会 409**：其他 AI 也在改/部署时，deploy 会报 409 冲突并中止——先拉线上版本对比（确认对方无独有内容后）再强制覆盖重部署；已多次发生（2026-08-02 与日志 AI 并发）
- 部署上传必须串行（GitHub 并发写返回 409）
- 手机/微信缓存顽固：改版加版本参数 `?v=`
- Token 在 `.env`，不硬编码、不在对话里传
