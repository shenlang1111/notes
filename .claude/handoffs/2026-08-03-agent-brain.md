## 2. 本轮讨论核心结论 — "大脑"方向（⚠️ 接替者必读）

用户经过多轮澄清，最终确认的架构方向（**这决定你接下来所有工作方向**）：

### 2.1 用户要什么 / 不要什么

| 用户要的 | 用户明确否决的 |
|---|---|
| 几个 AI **互通**，共享知识库当共同大脑 | "文档模拟的伪协作"（窗口不相通、靠改文档传话） |
| 在 Trae 发布想法 → **大脑实时接** → 自动分派 | **定时扫描**（要实时交互，不是每几分钟轮询） |
| **只解决困难部分**，简单任务留给 Trae | 所有任务都让后台 AI 做 |
| AI 之间**自己传消息**，省去用户人工传话 | 用户在中间当传话人 |
| 更好地**查找资料、更新想法** | "多一个帮你改东西的 AI" |

### 2.2 大脑的本质（我建 + 我运营）

```
        ┌──────────── 大脑（Claude Code 建 + 运营）────────────┐
        │  【消息信箱】任务板/草稿文件 ← 任何 AI 都能读写          │
  Trae  │  【自动调度】识别难任务 → 我认领执行，简单留给发布方     │
 闲聊AI │  【共享记忆】ai-worklog(谁干了什么) + 知识库(共同大脑)   │
 日志AI │  【自动回传】干完写回信箱 → 发布方读到结果，不用转达     │
        └─────────────────────────────────────────────────────┘
```

### 2.3 实时互通的物理基础

- 用户确认：**移动端和桌面端共享同一个文件夹**，移动端可调动桌面端 → Trae 发布的内容**立刻落在本地文件**。
- 因此用 **fs.watch 事件监听**（文件一变，毫秒级触发），**不是**定时轮询。
- 实时闭环：Trae 发布 → 共享文件夹文件变 → fs.watch 触发 → 我自动认领（只做难的）→ 翻库查资料/更新想法 → 写回信箱 + 留痕 → 用户在 Trae 看到结果。

### 2.4 技术要点（建大脑时必须处理）

1. **防死循环**：我干完活改文件也会触发监听 → 加"处理中标记"，让我改的不再触发自己。
2. **只做难的**：信箱里带"需要处理"标记的我才动；简单问题/闲聊不碰（留给 Trae）。
3. **消息协议**：定义"一条消息长什么样"（谁发的/发给谁/内容/状态），所有 AI 统一用它写信箱。
4. **常驻进程**：电脑一直开（用户已确认），监听进程常驻后台当大脑中枢。

### 2.5 双引擎分工（已确认）

| 窗口 | 定位 | 负责 |
|---|---|---|
| **Trae（主窗口）** | 前台·主对话 | 日常对话/答疑/移动端记想法/处理任务 |
| **Claude Code（智能体 AI）** | 后台·大脑 + 执行引擎 | 建大脑中枢、实时监听、只接难任务、翻库/更新/批量 |

分工标准：会不会把主对话窗口撑脏——轻的/顺手/高频 = Trae；重的/批量/占上下文 = 大脑自动分给我。

### 2.6 三条底层原则（之前讨论已确认，不废弃）

- **瘦上下文**：长期记忆存文件；窗口只放"身份+去哪查+本次任务"；干活开新上下文。
- **文件即记忆**：状态全落盘（ai-worklog/任务板/各页），上下文丢了可从文件恢复。
- **会话即进程**：一个大任务干完、结果落盘就开新会话，不硬撑。

## 8. 已知的坑（Gotchas）

- **部署超时/网络**：GitHub API 偶发 `fetch failed`（本轮遇到一次）→ 重试可过；部署超时（360s 构建限制）大文件多时可能发生 → 文件已上传则等构建或补触发。
- **同一文件必须串行编辑**：并行会互相覆盖，导致内容丢失。
- **部署上传串行**：GitHub 并发写返回 409，重试可过（deploy.js 已处理）。
- **验证线上用 Node fetch**：PowerShell 的 Invoke-WebRequest 可能误报 404。
- **手机/微信缓存**：改版后加版本参数 `?v=` 强制刷新，或让用户 Ctrl+Shift+R。
- **Token 安全**：在 `.env`，不硬编码、不在对话里传。
- **SessionStart hook 生效**：中途配置不触发，需重开窗口或 `/hooks` 重载。
- **fs.watch 防循环**（建大脑时）：处理中标记避免自触发死循环。
