### 对每个候选方案，逐项验证这 5 关（必须全部跑过）

| 关 | 验证问题 | 判定标准 |
|---|---|---|
| **① 可跑性** | 能不能装起来？依赖/环境/要不要联网/API key？ | 能装能跑 = ✅；装不上/太重 = ❌ |
| **② 接入性** | 能不能直接读现有 HTML+MD 文件？要不要转格式/向量化/建图谱？ | 能读文件 = ✅；强制专用格式 = ⚠️ |
| **③ 检索质量** | 是不是混合检索？有没有知识图谱/语义+关键词？ | 混合检索 = ✅；纯关键词 = ⚠️ |
| **④ 接入复杂度** | 几步能接进 Claude Code？（MCP / CLI / skill / 还是自研脚本） | 步骤少 = ✅；复杂改造 = ⚠️ |
| **⑤ 自进化能力** | 能不能自动沉淀记忆/自动生成 skill/后台整合？ | 有 = ✅；无 = ❌ |

> **诚实纪律**：这 5 关是"跑过才能填"，**不是搜到简介就抄**。每关都实际装一下、跑一下、验证一下结论，再填表。装不上的就明说"装不上"，不许美化。

### 验证过程要求

- **测试隔离**：所有安装/依赖都放临时目录（如系统临时文件夹），**不污染**正式库和 tools/。你验证期间改的任何文件都只在你自己的测试环境里。
- **真实数据**：用知识库里的真实片段做检索测试（比如拿"TC-MAB"、"TC-SHD"、某配方页的内容当测试问句），别用假数据。
- **记录过程**：每验一个方案，把"装了啥/跑了啥/结果如何/卡在哪"记下来，最后汇总成报告。

## 你的产出：一份《AI 大脑技术验证报告》

**写入** `knowledge-base/markdown/思考收件箱/`，命名 `brain-tech-verification.md`，并同步生成同名 HTML 版（双格式成对）。

报告必须包含：

1. **一句话结论**：主选 + 备选（比如"主选 deep-memory，备选 mem0"）
2. **五关打分表**：每个候选 × 5 关，逐格填 ✅ / ⚠️ / ❌ + 一句说明
3. **接入步骤**：对主选方案，给出"从零到接入知识库"的具体步骤
4. **风险与替代**：主选方案可能翻车的点、备选什么时候顶上

> 报告"完成"标准：五个候选都跑过、五关表都填了、有明确推荐。做不完全部也如实汇报进度（比如"只验了 deep-memory 和 mem0，BYO 装不上"），不许假装做完。
