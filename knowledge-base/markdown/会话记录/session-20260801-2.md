# AI 智能体构想 · 从"仓库"到"活人"

> 2026-08-01 闲聊记录。讨论让现有知识库进化为个人 AI 智能体的构想。

## 讨论背景

用户（天赐日化销售）在持续搭建知识库过程中，产生了更进一步的构想——不只是做一个"整理得井井有条的仓库"，而是做一个**活的智能体**，能主动联想、追问、消化知识，最终"像你，但比你懂得多"。

## 核心观点

### 现状：高级记录体，不是智能体

现有知识库的本质是**仓库**——把东西放进去，分门别类，需要的时候去翻。它做得再好也只是：
- 不会主动联想（"你三个月前说过这个事"）
- 不会追问（"这么想的原因是什么？"）
- 不会消化（只是存档，不是理解）

### 理想形态：三层结构

```
你的想法/资料 → 储存 → 检索 + 理解 → 输出像你的回答
```

- 现在的知识库解决了"储存"（HTML + MD 双格式）
- 缺的是"检索+理解"层（RAG）
- 以及"像你的回答"（人格化）

### 安全问题

用户担心 GitHub 仓库被入侵。结论：
- 静态网站本身没有攻击面（内容公开，无后端）
- 真正风险是 Token 泄露 → 已有防护（.env 不上传）
- 建议加一道：GitHub 两步验证（2FA）

## 方案对比

| 方案 | 路线 | 投入 | 效果 |
|------|------|------|------|
| 方案一 | Obsidian + AI 插件 | 零代码，半天 | 能检索，但不会主动 |
| 方案二 | 自建 RAG 智能体（Python + FastAPI + 向量检索） | 写少量代码，1-2 天 | 真正"活"的智能体 |
| 方案三 | Coze / Dify 等平台 | 拖拽式，10 分钟 | 快，但知识在第三方 |

**用户倾向方案二**，认为最接近理想。

## 方案二技术架构

```
用户（手机/电脑） → 网页聊天界面 → FastAPI 服务 → 查询 MD 知识库
                                               ↓
                                    向量检索 + LLM 生成回答
                                               ↓
                                          返回用户
```

| 组件 | 选型 | 说明 |
|------|------|------|
| 聊天前端 | HTML + 原生 JS | 单页，类似现有 mobile.html 风格 |
| API 后端 | Python + FastAPI | 轻量异步框架 |
| 向量检索 | 读取 MD 文件 + Embedding API | 不依赖额外向量数据库 |
| LLM | 硅基流动 API | 便宜，国内直连 |
| 人格系统 | 一条 system prompt | 从知识库文本提炼说话风格 |

### 新增文件结构

```
ai-agent/
├── agent.py              # 主程序（FastAPI 服务）
├── kb_loader.py          # 读取 MD 知识库，生成索引
├── retriever.py          # 检索模块
├── chat.py               # 对话逻辑（组装 prompt + 调 LLM API）
├── config.py             # 配置
├── requirements.txt      # Python 依赖
├── personality.md        # 人格描述
├── templates/
│   └── index.html        # 聊天界面
└── .env                  # API Key（不上传）
```

### 核心流程

**启动时：** 读取 `markdown/` 下所有 MD 文件 → 按段落切分 → 生成 Embedding 向量索引

**每次对话：** 用户发消息 → 检索最相关 3-5 个片段 → 组装 prompt（片段 + 风格 + 对话历史）→ 调 LLM → 返回回答

**每次结束：** 对话总结写回"会话记录"分区（HTML + MD 双格式）
