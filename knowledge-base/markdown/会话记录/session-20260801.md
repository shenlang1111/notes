# 会话总结 · 2026-08-01

## 本次会话摘要

- **部署通道**：git push 国内超时 → 改用 GitHub API（api.github.com）上传 + 触发构建。加速器时通时断不可靠；国内镜像站（ghproxy）不支持 push，不适用。
- **手机版修复**：footer 文案被截入每个面板（extractContainer 用 lastIndexOf 误截）→ 改为配对计数匹配，footer 重复问题消除；面板改用 div + cleanSections；每次打开强制回首页。
- **规范建立**：《知识库维护规范》v1.1 落地：内容架构、部署、手机版、会话协作、主 agent 规则、经验速查。
- **多会话协作**：主 agent 负责底层架构与部署；小改动各 agent 自理、大改动归主 agent；一键部署脚本 deploy.js + 本地 .env 管理 Token。

## 关键决策

| 决策 | 原因 | 结果 |
|---|---|---|
| 部署走 GitHub API | git push 在加速器关闭时完全不通 | api.github.com 稳定直连，Contents API + pages/builds 全流程可用 |
| mobile.html 修复根因定位 | footer 里的 div 导致 lastIndexOf 误截 | 配对计数匹配 container，footer 彻底排除 |
| 缓存用版本参数绕过 | 手机/微信浏览器缓存顽固 | 入口跳转加 ?v=2，部署后以服务器端抓取验证为准 |
| 建立主 agent 协作体系 | 多对话框同时操作同一文件夹 | 改动分级 + 单点部署 + 本地 .env 管 Token，防止互相覆盖 |

## 协作模式实践

- **多 Agent 并行**：本次实践部署（主 agent）与审核（审核 agent）并行执行，互不阻塞
- **审核 Agent 把关**：独立审核发现 deploy.js 6 处问题（1 中 5 低/提示），全部修复：--files 附带 mobile.html、构建轮询竞态、409 排队处理、footer 检查词扩展等
