# UI 美化可复用经验 v1

> 2026-08-03 · 天赐材料日化知识库全站 UI 美化经验沉淀

## 一、概述

对天赐材料日化知识库进行了全站 UI 美化，覆盖 34 个内容页 + 首页 + 全局 CSS/JS。产出 5 层可复用资产：

| 层级 | 资产 | 文件 | 复用方式 |
|------|------|------|----------|
| 1 CSS 组件库 | 12 个 token 驱动组件 | style.css | 换 :root 变量即套用 |
| 2 批处理脚本 | 全站批量注入组件 | batch-enhance.mjs | 改 registry 路径即跑 |
| 3 JS 注入模式 | 回到顶部/表格滚动/TOC折叠 | nav.js | 引 nav.js 自动生效 |
| 4 审核基准 | 5 层 20 项 checklist | 本页第五节 | 任何 UI 前后审核 |
| 5 工作流程 | 调研→方案→批处理→验证 | 本页第六节 | 任何美化项目 |

### 设计令牌体系

所有组件基于统一 CSS 变量：`--accent:#0B7666`、`--accent2:#14B8A6`、`--hero-grad`、`--shadow-xs/sm/md/lg`（四级阴影）、`--radius:14px`/`--radius-lg:20px`（两级圆角）。换一套 :root 就能改变全局视觉。

## 二、CSS 组件库（12 个）

| 组件 | CSS 类名 | 用途 | 关键特性 |
|------|----------|------|----------|
| 页面头 | .page-hero | 内容页顶部渐变头 | 深青渐变+光晕+面包屑 |
| 面包屑 | .breadcrumb | 页面位置导航 | 半透明白字+分隔符 |
| 快捷入口 | .quick-bar | Hero 区快速链接 | 胶囊按钮+hover上浮 |
| 统计快照 | .snapshot | 数字+标签网格 | 4列响应式+三色变体 |
| 最近更新 | .recent-updates | 更新时间线 | 日期+标题卡片条 |
| 本页目录 | .toc-nav | 章节快速跳转 | details折叠+编号网格 |
| 上下篇 | .page-nav | 页面间翻页 | 双列卡片+方向箭头 |
| 相关页面 | .related-pages | 同域推荐 | 图标+标题卡片网格 |
| 回到顶部 | .back-to-top | 浮动回顶按钮 | 滚动300px显隐+smooth |
| 表格容器 | .table-wrap | 数据表包裹 | sticky表头+滚动阴影+hover强调 |

### hover 动效统一规范

所有可交互卡片统一使用 `transition: all 0.22s cubic-bezier(0.4,0,0.2,1)`，hover 时 `transform: translateY(-2px~-4px)` + 阴影升级 + 顶部渐变条显现。不要用线性 ease。

## 三、批处理脚本用法

脚本 `batch-enhance.mjs` 核心逻辑：读 registry.json → 遍历页面 → 逐页注入 5 项增强。

### 注入的 5 项增强

| 序号 | 增强项 | 注入条件 | 效果 |
|------|--------|----------|------|
| 1 | CSS 版本号升级 | 含 ?v=6 | 缓存失效 |
| 2 | 面包屑导航 | 含 .page-hero 且无 .breadcrumb | 位置导航 |
| 3 | 本页目录 TOC | h3 数量 ≥ 3 且无 .toc-nav | 章节跳转 |
| 4 | 相关页面推荐 | 无 .related-pages | 同域4页推荐 |
| 5 | 上下篇导航 | 无 .page-nav | 按registry顺序衔接 |

### 3 步复用

1. 改 KB_ROOT 指向你的项目根目录
2. 准备 registry.json（pages 数组含 id/title/domain/file）
3. `node batch-enhance.mjs` → 全站一次性注入

注意：脚本自动处理已有 ID 的 h3（不覆盖）、相对路径计算、首尾页上下篇留空。

## 四、nav.js 注入模式

3 个自动注入功能，页面引用 nav.js 即生效：

1. **回到顶部按钮**：滚动超 300px 浮现，点击 smooth 回顶
2. **表格滚动检测**：比较 scrollWidth/clientWidth，可滚动加 .scrollable 类触发右侧渐变阴影
3. **TOC 移动端折叠**：窗口 ≤768px 自动移除 .toc-nav 的 open 属性

关键设计：零侵入（纯 JS 创建 DOM）、渐进增强（JS 不可用页面正常）、passive 监听（scroll 用 {passive:true}）、自动检测（不依赖手动标记）。

## 五、UI 审核基准（5 层 20 项）

达标线：第一层全过 + 第二三四层各过 80% + 第五层移动端全过。

### 第一层：基础合规（必须全过）

1. Token 一致性：颜色全走变量，无硬编码 hex
2. 间距系统：垂直节奏成倍数
3. 字体层级：最多 4 级字号
4. 色彩对比度：正文 ≥ 4.5:1（WCAG AA）

### 第二层：视觉质感（过 80%）

5. 阴影层次：卡片 xs/sm，hover md/lg，浮层 lg
6. 圆角统一：容器 14px，大容器 20px，小元素 8-10px，不超过 3 档
7. 渐变克制：只用于 hero 和表头
8. 留白节奏：区块间距 ≥ 内容间距 1.5 倍
9. 边框克制：能用阴影就不用边框

### 第三层：信息体验（过 80%）

10. 信息层级：3 秒识别三级结构
11. 扫视效率：卡片有图标+标题+描述
12. 导航完备：面包屑+返回+上下篇
13. 内容密度：表格 ≤ 7 列，段落 ≤ 4 行
14. 空状态处理：占位有视觉提示

### 第四层：交互细节（过 80%）

15. Hover 反馈：所有可点击元素有视觉变化
16. 过渡曲线：用 cubic-bezier 非线性
17. 状态一致：同类组件 hover 效果统一
18. 焦点可见：键盘 Tab 有 focus 样式

### 第五层：响应式适配（移动端必过）

19. 断点覆盖：768px 单列 / 769-1024 双列 / 1024+ 自适应
20. 触摸友好：点击区 ≥ 44px，表格有滚动提示

### 审核流程

截图存档（3 端 × 关键页）→ 逐层过 checklist 打 ✅/⚠️/❌ → ❌ 必修、⚠️ 评估 → 修复后重新截图对比 → 达标线验收。

## 六、工作流程

1. **调研业界方案**：WebSearch + WebFetch 抓取 Docusaurus/Stripe Docs/Vercel Docs，提取可复用模式
2. **出方案拍板**：分方向列具体改动项，用户挑要做哪些
3. **批处理脚本一次性铺全站**：写 Node 脚本读 registry，自动注入，34 页 3 秒
4. **抽查验证**：读 2-3 个页面确认结构正确
5. **预览确认**：本地 HTTP 服务器，浏览器实际看效果

核心原则：**脚本优先于手改**。超过 3 个文件的重复改动先写脚本，可复现、可回滚、可审计。

## 七、复用指南

### 前提条件

- 静态 HTML 页面 + registry.json（pages 数组含 id/title/domain/file）
- 全局 style.css 用 :root 定义设计令牌
- nav.js 负责导航渲染

### 4 步复用

1. 复制 CSS 组件（12 个组件样式 + :root 变量）
2. 改令牌（修改 :root 颜色/阴影/圆角）
3. 跑脚本（改 batch-enhance.mjs 的 KB_ROOT）
4. 审核验收（用 5 层 20 项 checklist）

适合场景：产品文档站、知识库、教程站、内部 Wiki、API 文档。不适合 SPA 或超复杂交互站点。
