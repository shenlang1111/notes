## 📌 本轮进展：双引擎分工方案（2026-08-02 晚，与智能体 AI / Claude Code 讨论）

**用户拍板：Trae 是主对话窗口（有移动端实时记想法，Claude Code 没有），继续用 Trae 处理任务；Claude Code（智能体 AI）定位为"重活执行引擎"。方向认可，任务由 Trae 登记、我认领执行。**

### 1. 核心矛盾

- **团队是"伪团队"**：多个窗口互不相通，靠改文档传话（handoffs/任务板/工作记录），状态靠人肉转达、边界靠话术约束——越用越重、越用越脆。
- **上下文膨胀 → AI 变笨**：上下文是注意力池，塞越多每条注意力越少；对话一长自动压缩，压缩有损。所以"内容进上下文"是消耗品，不是越存越好。
- **主窗口也会爆**：会话越往后越容易爆。治本不是"盼着够大"，而是"一个会话别活太久"——干完一个任务就开新会话（会话即进程）。

### 2. 方案核心（三条原则）

- **瘦上下文**：长期记忆存文件，不占上下文；窗口只放"身份 + 去哪查 + 本次任务"；干活开新上下文。本质 = 把翻库规则 fanku（渐进式检索、limit ≤500 行、禁止整页通读）推广成全库纪律。
- **文件即记忆**：状态全落盘（ai-worklog 谁干了什么、任务板任务到哪、各页 HTML/MD 改了什么）。上下文丢了可从文件恢复，损失只是"重述任务"。
- **会话即进程**：一个大任务干完、结果落盘，就开新会话继续，不硬撑。上下文是易耗品，文件才是记忆。

### 3. 双引擎分工（负载均衡）

| 窗口 | 定位 | 负责 |
|---|---|---|
| **Trae（主窗口）** | 前台·主对话窗口 | 日常对话/答疑/快速改内容；移动端实时记想法（采集）；处理任务（Trae 也处理任务，不只记想法） |
| **Claude Code（智能体 AI）** | 后台·重活执行引擎 | 批量/大文件/定时任务/部署/翻库修复；把记下的想法整理入库（收件箱 → 正式页） |

分工标准：会不会把主对话窗口撑脏——轻的/顺手/高频 = Trae；重的/批量/要跑脚本/占上下文 = 交给我，我给回结果。两边都不爆、都不笨。

### 4. 衔接机制（任务怎么到 Claude Code 手上）

- **任务板/收件箱当任务队列**：你在 Trae 里说一句 → Trae 登记到任务板（或收件箱）→ 我盯板认领 → 干完在任务板标 ✅ + 登记 ai-worklog → 结果回传。你照样只在 Trae 一个地方说话，重活我兜底。
- 若未来 Trae 能直接调我（而非仅靠文档传），负载均衡更顺——先把"文档交接桥"跑通，技术升级再优化。

### 5. 落地节奏（分步，不推翻重来）

1. 先做自动防爆：工作记录/日志超 N 条自动滚动归档（机制更新页"稳定即摘除"已有规则）；
2. 会话健康检查：开场自动报"这个会话多长、该续还是该开新"；
3. 定习惯：大任务干完、结果落盘后，主动建议开新会话，不硬撑；
4. 重活派子代理，主窗口永远薄。

**留待验证**：① Trae 移动端读/写知识库文件的能力，决定"记想法"是直接进库还是先攒草稿；② 若只能先攒草稿，由 Claude Code 做"草稿自动归位"（定时/批处理，正是其强项）。

## 一、用户的整体想法（深度理解）

你要的不是"一个更聪明的 AI"，而是**一支住在知识库里的、都认识你的专家团队**：

- **根基是知识库**：里面不只有产品知识，还要有"你这个人"——你做什么、你怎么想、你的事
- **成员是多个专业 AI**：想法、内容、设计、技术……各司其职，不是一个人干所有事
- **共享"懂你"档案**：每个 AI 开工先读它，所以每个 AI 都懂你——找谁都不用自我介绍、不用转达
- **你不当协调者**：谁干什么，AI 之间自己组织
- **一起成长**：像这个知识库一样，越用越懂你

**一句话**：要的是"一群懂你的专家"——以知识库为共同大脑、以"懂你"档案为共同记忆，各自专业、直接对话、共同成长。

## 二、讨论脉络（怎么走到这的）

1. **起点**：想要"更像我的、更聪明的、能储存我记忆的智能体"
2. **纠偏 1**：不要新建聊天窗口——AI 本身就是窗口，不需要额外程序/服务器/页面
3. **聚焦**：先不做性格（人格化推迟），先做"非常强的、和你相关的知识库"——AI 会翻库回答 + 知识库含你的信息
4. **纠偏 2**：不想靠"立规矩建文档"协调——想要 AI 真正组合成团队
5. **结论**：N 个专业 AI + 一份共享"懂你"记忆档案 + 共享知识库；每个 AI 都专业、都懂用户，用户直接找任何一个都行
