# 知识库健康度盘点

> 定期体检清单——让"库越用越准"可度量、可追踪。硬伤进任务板修复，数据缺口登记追踪。

## 一、为什么盘

翻库规则落地后，需要回答"库在变好吗"。定期盘点把问题暴露出来：硬伤进任务板修复，数据缺口登记追踪。这就是评估闭环。

## 二、五维检查清单

| 维度 | 查什么 | 通过标准 |
|---|---|---|
| ① 双格式成对 | HTML/MD 是否成对 | deploy 成对校验无缺对告警 |
| ② 数据来源 | 具体数值是否标来源 | 无"裸数据当权威"；至少标"待核实" |
| ③ 硬伤扫描 | 错误/矛盾/误导表述 | 无已知硬伤残留（修复后才关闭） |
| ④ 深度与落点 | 是否达"为什么"+销售落点 | 无纯罗列页；知识页能落到客户场景 |
| ⑤ 翻库实测 | fanku 能否跑通 | 随机 2 个知识问题 → 带出处、不编造 |

## 三、盘点流程

- **触发时机**：每周一次 ｜ 攒够 5 条用户反馈 ｜ 大改动后。三者任一即可。
- **执行方式**：子代理并行读页 → 按五维逐页评分 → 汇总盘点报告。硬伤进任务板，修复后复检关闭。
- **产出**：盘点报告（各页评分 + 硬伤清单 + 数据缺口清单）+ 任务板登记。记录在"历次盘点记录"。

## 四、历次盘点记录

**2026-08-02（首次盘点，智能体 AI 执行）**
- 范围：14 个知识页（基础/四大表活/实战/配方市场四组并行）
- 结果：评分 B~D（nonionic D / properties C / market C / cationic C）；发现 8 条硬伤——已全部修复上线
- 遗留：全库 60+ 处数据无来源 → 已统一标"待核实"，等产品手册/TDS 补真实来源（见任务板）

**2026-08-02（第二次盘点，智能体 AI 执行）**
- 范围：3 个转换生成大页（finechem-engineering / tinci-surfactant-guide / tinci-amphoteric-summary）
- 结果：三页均 C（数据来源 D、结构 C）——牌号统计矛盾（23 vs 29）、命名与已核实信息脱节（TC-MAB INCI Coco/Lauro、GCK30P 旧名、市占率 32.6%/31.8% 矛盾）、章节乱序/内容错位/整段重复、渗透压机理错误、来源清单 MD 丢失
- 处理：硬伤已登记任务板（大改动待主 AI）；共性根因 = 转换脚本生成 + 页面过大（三页均建议拆分）
- 机制健康结论：无摆设机制；提醒各 AI 养成 ai-worklog 登记习惯、明确 ai-worklog（谁干了什么）与 CHANGELOG（库改了什么）边界

**2026-08-02/03（第三次盘点 + 全面修复，智能体 AI 执行）**
- 范围：全库健康度修复（约 20 文件）+ 3 个转换大页拆分 + 命名冲突修复
- 结果：第二次盘点硬伤**全部修复 ✅**——①精细化工拆 3 页（additives/daily-chem/surfaces）+ 渗透压机理修正 + 章节重排 ②天赐学习手册拆 3 页（product-overview/surfactant-details/market-sales）+ 市占率统一 31.8% + 命名修正 ③两性表活目录原地修复（牌号 23→29、TC-MAB INCI Coco→Lauro、RSPO 5→4）④文档事实/结构/内容硬伤修复（troubleshooting hero、amphoteric 5.3.2、synthesis 第 8 章编号）⑤称呼统一（智能体搭建 AI→智能体 AI）⑥跨页命名冲突修复（TC-SHD 50/B→TC-SHD(L)/(B)、TC-MAB 40CD→40LDL，全库无残留）
- 遗留：全库 60+ 处"待核实"数值待产品手册/TDS 到位后逐条补来源（见任务板，待认领）
